# シナリオ保存形式仕様（v1）

本ドキュメントは、シナリオ駆動の開発ハーネスにおける **登録側・見張り側・可視化（TUI）側・通知側** の共通約束事となるシナリオファイルの保存形式を定義します。

## 1. 配置とファイル名

- 対象プロダクトのリポジトリ内（既定: `scenarios/`）に Markdown ファイル（`.md`）として配置します。
- 推奨ファイル名: `<連番2桁>-<id>.md`（例: `01-rio-herdr-cross-machine.md`）。
- 1 ファイルにつき 1 シナリオを記述します。ユーザーはファイルを足すだけでシナリオを何本でも追加でき、既存ファイルは壊れません。

## 2. 全体構造

シナリオファイルは **YAML front matter** と **Markdown 本文** から構成されます。
自然言語の本文（`## 概要`）の下に、検証可能なステップ（`## ステップ`）と各ステップの OK 条件チェック項目が並びます。

```markdown
---
id: <kebab-case-id>
title: <シナリオの短い題名>
priority: P0
status: pending
last_checked_at: null
last_checked_by: null
notified_pass_at: null
tags:
  - core-workflow
---

## 概要
このシナリオで実現したい使い方・目的を自然言語で書きます。
エージェントによる状態書き戻し時、このセクションは一切改変されません。

## ステップ

### Step 1: <ステップの題名>
- status: pending

- [ ] [auto] s1-c1: <コマンドや SSH 等で自動検証できる OK 条件>
- [ ] [manual] s1-c2: <実機 GUI や操作感など人が確認する OK 条件>
```

## 3. YAML Front Matter 仕様

| フィールド | 必須 | 型 / 値 | 説明 |
| :--- | :---: | :--- | :--- |
| `id` | 必須 | kebab-case 文字列 (`^[a-z0-9]+(-[a-z0-9]+)*$`) | シナリオ識別子。同一ディレクトリ内で一意であること。 |
| `title` | 必須 | 非空文字列 | 一覧や通知に表示するシナリオ名。 |
| `kind` | 任意 | `scenario`（既定） \| `togaki` | 本筋シナリオ（`scenario`）か、親にぶら下がる枝葉・品質要件のト書き（`togaki`）か。 |
| `parent` | 条件付き必須 | kebab-case シナリオ ID | `kind: togaki` のとき必須。同一ディレクトリ内の親シナリオ ID を指定する（循環禁止）。 |
| `attach_step` | 任意 | 1 以上の整数 | `kind: togaki` が親シナリオの特定ステップに紐づく場合に指定。 |
| `priority` | 必須 | `P0` \| `P1` \| `P2` \| `P3` | 優先度（`P0` が最優先）。 |
| `status` | 必須 | `pending` \| `in_progress` \| `passed` \| `failed` \| `ready_for_manual` | シナリオ全体の状態。 |
| `last_checked_at` | 任意 | `null` または RFC 3339 日時文字列 | 見張り役が最後に検証した日時（例: `2026-11-25T09:30:00+09:00`）。 |
| `last_checked_by` | 任意 | `null` または非空文字列 | 最後に検証した主体（例: `codex`, `agy`, `claude`, `manual`）。 |
| `notified_pass_at` | 任意 | `null` または RFC 3339 日時文字列 | 全ステップ通過（または確認待ち）の通知を送った日時。重複通知の防止に使用。 |
| `tags` | 任意 | 文字列配列 | 検索・重複検出の補助タグ（既定: `[]`）。 |
| `hosts` | 任意 | 文字列配列 | 複数マシン検証で対象となる SSH ホスト名一覧（例: `["mac-studio", "ubuntu-4090"]`）。見張り役プロンプトへ自動注入されます。 |

未定義の拡張キーが front matter に含まれていても形式エラーにせず、書き戻し時に保持します。

## 4. 本文セクション仕様

### 4.1 `## 概要`（必須）
- 1 行以上の自然言語による説明が必要です。
- ユーザーが本当に試したい使い方や背景を書きます。状態更新時に書き換えられません。

### 4.2 `## ステップ`（必須）
- `## 概要` の後に配置します。
- 1 つ以上のステップ見出し `### Step <N>: <タイトル>` を含みます。
  - `<N>` は `1` から始まる連番（`1, 2, 3, ...`）でなければなりません。
  - `<タイトル>` は非空文字列です。

### 4.3 ステップのメタデータ行
ステップ見出しの直後に `- <key>: <value>` 形式で記述します。

| キー | 必須 | 値 | 説明 |
| :--- | :---: | :--- | :--- |
| `status` | 必須 | `pending` \| `in_progress` \| `passed` \| `failed` \| `ready_for_manual` | このステップの状態。 |
| `failed_check` | 条件付き必須 | `<check-id>` | `status: failed` のとき必須。失敗したチェック項目 ID を指定する。 |
| `summary` | 任意 | 非空文字列 | ステップ結果の短い補足。 |

### 4.4 チェック項目（OK 条件）
各ステップに 1 つ以上のチェック項目を記述します。

```text
- [<state>] [<mode>] <check-id>: <OK条件の説明>
  - reason: <失敗理由や補足（任意・失敗時に推奨）>
```

- **`<state>`（状態記号）**
  - `[ ]`: `pending`（未検証／手動確認待ち）
  - `[x]`: `passed`（通過）
  - `[!]`: `failed`（失敗・停止）
- **`<mode>`（検証区分）**
  - `[auto]`: 見張り役エージェントがコマンド・テスト・SSH 等で自動検証する項目。
  - `[manual]`: GUI の描画や操作感など、実機で人が確認する項目。見張り役はスキップして既存の状態を保持する。
- **`<check-id>`（チェック項目 ID）**
  - `^[a-zA-Z0-9][a-zA-Z0-9_-]*$` に一致する文字列（推奨: `s1-c1`, `s2-c2`）。
  - 1 つのシナリオ内で一意であること。
- **`  - reason: ...`（任意）**
  - チェック項目行の直下に 2 スペース以上インデントして記述する。失敗原因や見張り役の所見を短く残すために使用する。

## 5. 状態の整合性ルール

形式チェッカ（`daihon validate`）は、チェック項目の状態とステップ・シナリオ全体の状態に矛盾がないことを検証します。

### ステップ状態
- **`failed`**: 1 つ以上の項目が `[!]` であり、かつ `failed_check` がそのステップ内の `[!]` 項目 ID を指していること。
- **`passed`**: ステップ内の全項目（`auto` / `manual` 問わず）が `[x]` であること。
- **`ready_for_manual`**: `[!]` 項目がなく、`auto` 項目がすべて `[x]` であり、かつ未確認（`[ ]`）の `manual` 項目が 1 つ以上残っていること。
- **`in_progress`**: `[!]` 項目がなく、一部の項目が `[x]` であり、かつ未検証（`[ ]`）の `auto` 項目が 1 つ以上残っていること。
- **`pending`**: 全項目が `[ ]` であること。

### シナリオ全体状態（front matter の `status`）
- **`failed`**: いずれかのステップが `failed` であること。
- **`passed`**: 全ステップが `passed` であること。
- **`ready_for_manual`**: `failed` のステップがなく、全ステップの `auto` 項目がすべて `[x]` であり、かつ未確認の `manual` 項目が 1 つ以上残っていること（全自動チェック通過・ドッグフーディング可能状態）。
- **`in_progress`**: `failed` のステップがなく、1 つ以上の項目が `[x]`（またはステップが `in_progress`）であり、かつ未検証の `auto` 項目が残っていること。
- **`pending`**: 全ステップが `pending` であること。

## 6. 状態書き戻しの原則

見張り役や手動チェックコマンドがシナリオファイルを更新する際は、以下を守ります。

1. `## 概要` およびその他の自由記述セクションは 1 文字も変更しない。
2. front matter の状態欄（`status`, `last_checked_at`, `last_checked_by`, `notified_pass_at`）と、ステップの状態行・チェック状態行・`reason` 行のみを最小差分で更新する。
3. 新規シナリオ登録時は既存シナリオファイルに触れない。

## 7. 形式チェックコマンド

```bash
# 既定ディレクトリ（scenarios/）または指定ファイル／ディレクトリを検証
daihon validate examples/scenarios
daihon validate examples/scenarios/01-rio-herdr-cross-machine.md
```
